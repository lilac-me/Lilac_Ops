# 端到端收益优先（P0 强制验收）

算子优化是手段，整网真实收益是目标。单算子 latency/MFU、kernel 累计耗时占比、减少 launch 次数、理论带宽收益均不是最终验收证据。优化前先明确当前 workload 的整网主指标和约束，优先选择位于实际关键路径、未被通信/计算掩盖、有可观测收益潜力的候选。热点排名只作线索；缺关键路径证据时标记估计不确定，不把 kernel 时间累计量当作整网墙钟时间。

先锁定模型、设备、版本、并行、精度、输入数据及真实工作量，关闭 profiler 进行基线和回归；采集单独执行。首次实机以一个候选/一组不可拆分的融合为单位对照，避免多个修改互相掩盖。优化后必须实际运行原框架并验证精度、主指标及保护指标。没有整网收益、收益落在噪声内、精度失败、测量不可比或没有测量的候选不计入有效优化；退化或不达最低收益时回滚/不合入，保留单算子证据和诊断。批量优化的整网收益只能归因到整个补丁集合，不冒称每个单算子贡献。生产采纳前建议至少三组独立前后对照，预热一致，检查每组及总体波动；单次对照只作初筛。阈值在测试前确定，并依据 baseline 波动提高，不能看到结果再降低。所有报告明确区分单算子实测、整网实测、预测与未验证。

训练：固定 checkpoint、数据顺序、seed、拓扑及每步真实 token 数，比较平均及中位 Step Time、吞吐（实际 tokens 已提供时）及逐 Step Loss。当前 engine 默认 min_step_improvement_pct=1.0：平均 Step Time 至少降低 1%，中位 Step Time 必须改善，loss 必须通过原精度门禁。小于阈值即拒绝保留本轮补丁；可按基线波动设置更高的正阈值。max_step_regression_pct 保留兼容诊断，但不允许用其绕过正收益门禁。现有一次 baseline/一次 regression 仅为首轮筛选；正式稳定性仍需多次独立复测。通信、显存或集群等未来场景可另定义对应的有效训练吞吐/规模/可靠性目标，不在本轮扩展。
