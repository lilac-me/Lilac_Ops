# 端到端收益优先（P0 强制验收）

算子优化是手段，整网真实收益是目标。单算子 latency/MFU、kernel 累计耗时占比、减少 launch 次数、理论带宽收益均不是最终验收证据。优化前先明确当前 workload 的整网主指标和约束，优先选择位于实际关键路径、未被通信/计算掩盖、有可观测收益潜力的候选。热点排名只作线索；缺关键路径证据时标记估计不确定，不把 kernel 时间累计量当作整网墙钟时间。

正式验收统一使用 AISBench 流式压测。固定模型、设备、版本、真实请求集、实际输入输出 token、请求并发/到达率、采样、KV cache 冷暖、graph、量化与拓扑。关闭 profiler 进行基线和回归，采集单独执行。首次实机以一个候选/一组不可拆分的融合为单位对照，避免多个修改互相掩盖。

明确主目标：固定负载下 Output Token Throughput 提升，或在吞吐/SLO 约束下 TTFT/TPOT 降低，或固定 SLO 下 goodput 提升。首轮建议预设至少 1% 正收益门槛且高于 baseline 噪声；Mean/P99 TTFT、TPOT、ITL、E2E、成功率、输出工作量及独立精度对照均作为保护指标。默认其他关键指标不能超出预先约定的容差/SLO；未预设权衡不得拿一个指标提升掩盖另一指标退化。

至少三轮前后压测，原始数据、实际 tokens 和逐请求结果可追溯。阈值在测试前确定，并依据 baseline 波动提高，不能看到结果再降低。单次对照只作初筛。只做了 kernel 优化或 CLI 返回成功，标记 NOT_VERIFIED；没有收益、收益落在噪声内、精度失败、测量不可比或没有测量的候选不计入有效优化；无收益则 NO_E2E_GAIN 并拒绝合入或回滚，保留单算子证据和诊断。批量优化的整网收益只能归因到整个补丁集合，不冒称每个单算子贡献。报告明确区分单算子实测、整网实测、预测与未验证。

当前 AISBench 自动解析和服务回归编排尚未实现，此规则由实际测试及人工验收执行，不冒称自动门禁。量化、池化、PD 等专项能力仍待算子闭环稳定后扩展。


## 单算子事务（当前执行原则）

每轮从当前已保留的服务版本出发，只选一个热点算子或一个不可拆分的融合算子组。CANNBot 自主多轮分析、代码修改、精度与性能测量，按其内层退出条件交付最佳合格实现；不要求每次单算子迭代都重启整网。然后只集成这个算子，在相同 AISBench workload 下进行整网对照。只要主指标真实正收益超过预设噪声门槛、精度及保护指标不劣化，就保留该版本；不强求固定单算子加速比或 MFU。失败或无收益则回滚。下一个算子必须从最新保留版本重新建立 baseline，不能同时混合多算子改动。显式 dispatch 入口每个 analysis run 只允许选择一个 task；重试仅可针对同一个 task。直接通过 Agent 调用插件时也须遵守此原则。当前服务级自动集成、AISBench 自动解析/回归仍未实现，先在隔离环境实测验收。
