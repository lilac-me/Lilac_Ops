# RL Case Guard 测试前全量用例说明

本模板只用于 `model-rl-case-guard` 的模型开箱验证，不是整个 MindSpeed-Agent 仓库的测试列表，也不把脚本自身的离线回归测试作为模型测试项。首次回复展示以下上下文、前置说明和**完整表格**；随后依据本轮已确认信息填写实际安排，不能删掉未执行项。各项的参数和详细操作仍以 [feature-matrix.md](feature-matrix.md)、[multi-node-weight-update.md](multi-node-weight-update.md) 和 [performance-and-evaluation.md](performance-and-evaluation.md) 为准。

## 打屏上下文

面向使用者显示标题“RL Case Guard 全量用例说明与本轮计划”，并填写：

- 模型、权重路径与版本；权重范围为真实全层或减层随机权重。
- 单机/多机、节点与设备数、计划 TP/PP/DP/EP 和图模式。
- baseline 公共特殊配置是否已明确，以及本轮报告目录。

尚未确认的信息写“待核实”，不捏造配置、测量值或已通过结论。不在展示中包含密码、token 等凭据。

## 前置准备说明

先向使用者说明以下是测试前的准备工作，不计为特性通过：

1. **环境与资产核查**：检查模型配置、代码和权重、依赖版本、节点/NPU、必要环境修改及 PR；固化 baseline 特殊配置，完成容量预检。容量不满足时输出阻塞报告并终止后续测试。
2. **可选减层权重生成**：只有 config 且用户选择快速验证时，保留基础结构生成减层随机 checkpoint。此模式仅验证功能路径，不能作为真实模型准确率、完整规模或性能验收结果。
3. **评测选择**：真实全层权重时在开始阶段询问是否跑数据集及生成长度。评测未选或信息未补齐，不影响其他独立项按既有规则执行。

## 展示后的执行规则

- 以“计划执行”“待核实”“按需未选择”“不适用”“用户明确排除”“阻塞”等说明本轮安排，并附实际原因。只有执行结束取得证据后才写 `passed` / `failed`；最终报告中的 `not_run` / `blocked` 需说明原因。非 MoE 等不适用项保留在计划中，最终按现有报告格式记录未运行原因。
- TP、DP、EP 和图模式可在同一份基础配置中验证，但在本表和最终报告中分别说明；不是额外要求为每项都重启一次服务。HCCL、IPC、Checkpoint，及 DCP、PCP、SP、PP 分别记录，不能合并成一项通过。
- 第 08 项是随第 09–11 项执行的验证维度，不额外调度一个不存在的 level-2 脚本。`test_sleep_mode.py` 仅覆盖 level-1；level-2 的状态及内存证据可在权重更新流程中补充采集，或使用目标版本原生测试。未采集的检查明确记录为未验证，不从权重更新成功推导全部通过。
- 打屏后按已授权流程继续，**不因展示本表而等待额外批准**。必要的输入、原有容量门禁和配置确认仍按主入口执行。
- 每项开始前向使用者输出“【开始验证：用例名称】”，简述本项目标、实际配置与判定方式，再展示实际命令。执行结束输出状态和证据路径；条件变化时更新计划，不能用“看起来可选”省略默认项。
- 将实际展示的上下文、前置说明和完整表格保存到任务目录 `test-plan.md`，在任务 manifest 中记录路径；保留不适用、用户排除和阻塞的行，便于最终报告解释覆盖范围。
