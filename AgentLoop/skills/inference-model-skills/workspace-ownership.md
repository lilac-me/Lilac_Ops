# 工作目录与归属

serving 服务与 AISBench 环境准备使用以下个人运行目录：

- serving 服务运行目录：`/home/<工号>/serving/<实例>/`。
- AISBench 环境准备日志：`/home/<工号>/aisbench/`。

启动上述流程前，使用上下文中用户明确提供的个人工号；未知或无法确定时必须先向用户询问。不要使用共享 SSH 账号、Git 配置、公钥注释或他人容器名推断工号。通过 `--employee-id <工号>` 传入，放在透传参数或分隔符之前。多机 serving 的 head 和 worker 使用同一工号。

服务从各自的实例运行目录启动，PID、stdout/stderr 和日志保存在该实例下，以隔离不同服务，并避免源码目录或同名文件遮蔽 Python 导入。Docker 模式使用容器内路径；目录不可写时报告原因，不回退到共享目录。

benchmark、profiling 等调用 serving 的入口负责透传工号；客户端工作目录、仓库、数据集、媒体白名单和数据输出目录遵循各 Skill 自身约定。本地 `.workspace-local/` 状态与报告遵循对应入口的约定。

本规则适用于显式引用本文的流程。查询状态、停止已有服务及只读资源探测不要求工号。
