# 模型档案卡模板（执行状态载体，每模型一份，跨阶段唯一读入）

> 复制为 `<目标仓>/.npu-migration/<Model>/model-card.md`，与**同目录的 `pitfalls.md`** 分开：档案卡是执行状态载体（跨阶段读它），踩坑记录是知识沉淀（给后续模型参考）。
> 用途：A→B→C 跨阶段的压缩载体：当前阶段结束后把结论写进「检查点」（≤20 行替换式更新），
> 后续阶段决策只引用档案卡，不回溯过程细节。

```markdown
# 模型档案卡：<模型名>

- 上游仓库 / commit: <url> @ <commit>
- 结构: 主干 <xx> / 头部 <xx> / 分片·并行策略 <xx>
- attention 实现: <transformers 直出 | 非 transformers 手写 | TE/DiT 专有>  → 决策命中 <../references/flow/1-migrate.md §3.4 ①|②|③>
- Tier 判据:
  - Tier1（迁移期）: <如 device 字符串裸写 / AMP 精度错 / fp64 算子无实现>
  - Tier2（优化期）: <如 DeepSpeed→FSDP2 换装 / 融合算子缺失>
- 参考模型（`../references/ref-models.md` 反查）: <2~3 个，标语料引用|实测>
- 数据流一页纸（A 阶段静态分析的产出，一页以内）:
  入口 <启动脚本 → 主函数> → dataloader <…> → 前向 <…> → 损失 <…> → 反向 <…> → 优化器 <…> → 存档 <…>
- 基线: seed=<固定> / 关键 loss=<xx> / 对齐结论=<与 GPU 基线 diff 或首测>
- 口径注册（性能数字自带；缩卡跑标「仅本口径有效」）:
  卡数/slice · batch(global×micro×grad-acc) · num_workers · 验证步数(前反向跑通，≥3) · 步时口径(**多步均值，跳过 warmup**) · 备注
- 阶段产物索引:
  - A: scan= / diff= / smoke=
  - B: prof= / ab=
  - C: patch= / test= / migration_log=
- 阶段状态: A<✅|🔄|❌> → B<...> → C<...>
- 检查点（阶段边界压缩, ≤20 行, 替换式更新）:
  - A 结论: <迁移完成: 冒烟 N 步 loss=xx / 基线已归档 / 环境细节已封存>
  - B 结论: <优化清单: 手段→数值→结论; 失败项一行一条>
  - C 结论: <交付产物路径 / `../references/ref-models.md` §已完成案例 已登记>
- 隐患备注:

## 优化记录表（B 阶段随做随记）

| # | 优化项 | 卡数 | StepTime / FPS 前 → 后 | profiling 省在哪 | 对齐结果 | 结论（保留/回退+原因） |
| --- | --- | --- | --- | --- | --- | --- |

| 2 | <失败的项也记一行> | | | | | <回退：无收益> |

```

## 审计凭据段（冗余审计的对账依据，A 阶段随改随记）

> 凭据**只是线索，不是豁免**：C 阶段仍须逐 hunks 回退验证（`git apply --reverse` 试删 / 编译启动确认行为不变），
> 凭据帮你快速定位「哪些是人工耦合点、哪些是工具覆盖」，不替代验证。**A 阶段随改随记在本卡**（工作区过程记录），
> **C 阶段整理进交付产物 `MIGRATION_LOG.md`**（必需产物，给人看「改了哪些 + 为什么」），每条一行。

```markdown
## 审计凭据（随改随记，C 阶段对账）

| 改动位置 | 改了什么 | 为什么（依据） | 工具覆盖不到? | 证据类型 | C 阶段回退验证结果 |
| --- | --- | --- | --- | --- | --- |
| <file:line> | <如 if dev == "cuda" 分支移 npu 逻辑> | <控制流字面量：transfer 只兜 API 实参，够不到分支判断> | 是 | <运行时探针 / A-B 实验 / 静态推理 / 机械必要> | <反向试删后行为? 保留/删除> |
| <file:line> | <如 device.startswith("cuda") 分支放行 npu> | <控制流守卫，不放假走 fp32> | 是 | <静态推理> | ... |
| <file:line> | <如 torch.load(map_location="cuda") 未改（交给 transfer_to_npu）> | <工具覆盖：白名单函数 + 4 个关键字实参名之一（实测）> | 否 | <运行时探针> | <已确认无手改残留> |
```

- 覆盖规则：`transfer_to_npu` = **白名单函数 × 4 个固定形参名**（`device` / `device_type` / `map_location` / `device_id`）：完整范围与边界见 `../references/flow/1-migrate.md` §3.2，**不要把所有带 `device=` 的调用都当成工具能兜**（非白名单的第三方 / vendored 调用点必须自己改）。白名单内的源码改动一律不留在 diff；必须留的是控制流/定义级字面量、`torch.device(...)` 构造对象的下游使用、f-string 设备串（`../references/flow/1-migrate.md` §3.3）。
- 防误判：凭据写「工具覆盖不到? = 是」的改动，C 阶段仍要走一遍回退验证再确认保留（防止「当时叠加依赖效应」记错）；凭据漏记的改动以 `git diff` 为准逐 hunks 复查，凭据清单不等于改动全集。
