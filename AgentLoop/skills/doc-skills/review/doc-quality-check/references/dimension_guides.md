# 四维检查细则（dimension_guides）

> 每项检查以 rules/rules.yaml 的规则为准（rule_id / 判定方式 / linter）；本文件给出语义判定的操作细则与常见模式。

## 正确性（correctness）

| 规则 | 检查内容 | 判定要点 |
| ------ | --------- | --------- |
| R-COR-001 | 链接有效 | 确定性：lint link 子模块；跨仓分支与目标仓由 R-COR-004 复核 |
| R-COR-002 | 代码示例可运行（静态） | 确定性：lint code 子模块（语法 + 目标仓符号引用）；实测归 R-COR-009 |
| R-COR-009 | 代码示例验证闭环（分级实测） | 每块分级：T1 直接执行（shell/仓内脚本）、T2 构造最小脚本（python 片段）、T3 仅静态核对（配置/参数、多机多卡大资源命令）；有 NPU 环境 T1/T2 实测（附命令+输出），无环境标 manual 待人工验证；T3 以与代码定义一致为准；缺结论/证据即记问题 |
| R-COR-003 | 参数与实现一致 | 参数名/类型/默认值/取值范围对照代码定义 |
| R-COR-004 | 版本与配套一致 | 版本号与配套表对照发布说明；跨仓分支与目标仓复核 |
| R-COR-005 | 代码注释准确 | `#`、`//` 注释与代码行为/参数语义一致，无过时误导 |
| R-COR-006 | 插图真实无伪造（证据链审查） | 截图与运行记录成对（采集环境/命令/版本）、交付记录完整、内容与文档版本一致；未交付占位不得声称存在（闭环由 R-COM-008 确定性检查）；**不声称机器识别 AI 生成/伪造**，真伪最终归人工交付责任 |
| R-COR-007 | 语义与实现一致 | 功能行为、特性能力、限制条件、适用场景与实际实现一致 |
| R-COR-008 | 数据口径准确 | 指标口径、性能数据标注（硬件/版本/复现条件）完整准确 |

## 完整性（completeness）

| 规则 | 检查内容 | 判定要点 |
| ------ | --------- | --------- |
| R-COM-001 | 仓库必备资料齐全 | 对照 templates/repo_manifest.yaml：必备与条件资料（按仓库能力 models/toolchain）在仓内可定位（files glob 或 H1/H2 标题匹配）；可选资料不强制（确定性由 lint manifest 子模块给出） |
| R-COM-002 | 前置条件完整 | 硬件/软件/数据权重/权限网络逐项 |
| R-COM-003 | 成功标志明确 | 每类操作给出可验证结果（日志关键词、产物文件、命令输出） |
| R-COM-004 | 错误处理覆盖 | 常见失败有定位入口 |
| R-COM-005 | 交叉引用存在 | 引用目标存在且正确 |
| R-COM-006 | 无占位符 | TODO、`<...>` 等未填充内容 |
| R-COM-007 | 版本信息标注 | 版本号与配套信息标注完整 |
| R-COM-008 | 插图诉求齐备 | 正文占位与 figure_requests.json 一一对应，占位规范、替代文本草案存在；缺失图片不得声称已交付 |

常见缺项模式（供语义复核；确定性缺失由 lint manifest 子模块给出）：

- 仓库形态 → 能力映射：模型仓 → repo_has_models；提供工具链 → repo_has_toolchain
- 必备资料在 README 章节形态与独立文档形态均可（检测规则见 repo_manifest.yaml 头部注释）
- 章节级结构不做强制校验；设计者自拟章节清单仅作撰写参考

## 易理解（clarity）

| 规则 | 检查内容 | 判定要点 |
| ------ | --------- | --------- |
| R-CLA-001 | 逻辑连贯 | 章节顺序与因果链顺畅 |
| R-CLA-002 | 术语定义 | 首次出现的专业术语有定义或入口 |
| R-CLA-003 | 段落长度 | 以单段 ≤5 句为宜；长段有充分理由（复杂概念、代码/表格上下文）时不强求——最低档提示，不阻塞 |
| R-CLA-004 | 示例质量 | 示例贴切、可理解、与受众匹配 |
| R-CLA-005 | 标题密度 | 每 200~400 字有标题 |
| R-CLA-006 | 主动语态 | 以用户可执行的动作表述 |
| R-CLA-007 | 受众匹配 | 难度与目标读者一致（使用者：操作导向；开发者：术语可密集但首现定义） |
| R-CLA-008 | 错别字简繁 | 正文/表格/标题 + 代码块注释；简繁混用、全半角混用 |

## 易获取（accessibility）

| 规则 | 检查内容 | 判定要点 |
| ------ | --------- | --------- |
| R-ACC-001 | README 导航 | 入口文档在 README 可达 |
| R-ACC-002 | 关键资料入口 | 安装/快速开始/FAQ 等有一级入口 |
| R-ACC-003 | 跳转步数 | 3~5 步内可达（≤2 步直达不算问题；>5 步记问题） |
| R-ACC-004 | 搜索友好 | 标题与关键词便于检索 |
| R-ACC-005 | 跨仓导航可达 | 跨仓引用能从入口沿导航到达；链接有效性归 R-COR-001，本规则只查导航路径 |
| R-ACC-006 | 导航一致性 | README 入口章节与实际目录树一致（新增/删除文档同步登记） |
| R-ACC-007 | 图片路径有效 | 文件存在（替代文本归 R-COM-008） |

入口基线以 `repo_manifest.yaml` 与仓库能力为准（必选性由 lint manifest 子模块确定性检查，语义复核不重复判定）：

- 恒必选的入口：简介（D-INTRO）、安装指导（D-INSTALL）、快速开始（D-QUICKSTART）、版本说明（D-RELEASE）、FAQ（D-FAQ）；
- **模型与特性入口仅承载模型内容的仓（repo_has_models）必选**：有模型仓为"支持模型/特性"（D-MODEL-SUPPORT），加速库/适配器仓无模型介绍，仅以"支持特性"形态存在（D-MODEL-SUPPORT 标题自适应口径，见 portfolio_guide）；
- 入口形态：README 章节或独立文档均可；语义复核只查入口可达性与导航一致性（R-ACC-001/002/006），不查清单必选性。
