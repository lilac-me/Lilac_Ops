# 通用写作规范（writing_guidelines）

1. **标题与开头**：`# 文档标题` 后 3~5 句概述段，说明文档目的、读者、适用范围。
2. **章节层级**：H1 仅用于标题；正文从 H2 起，最多 4 级；每 200~400 字至少一个标题。
3. **前置条件显式化**：硬件、软件、权限、网络、数据、权重，缺一不可的必须单列。
4. **成功标志明确**：每类操作给出可验证结果（日志关键词、产物文件、命令输出）。
5. **代码块纪律**：命令可复制执行；占位符 `<...>` 给出说明；`#` 注释保留并纳入审查。
6. **表格统一**：支持矩阵、参数表、配套表使用统一列定义；空值用 `-` 并说明含义。
7. **链接规范**：同仓优先相对链接；跨仓链接遵循版本分支规则；新增文档必须登记到 README 对应入口章节。
8. **命名规范**：文件名小写下划线；README 类固定 `README.md`；同型多实例用目录名区分。
9. **语言风格**：主动语态、术语统一（简体中文、无错别字/简繁混用）。
10. **插图规范（人工输出）**：Agent 不生成、不编造插图与截图（含 AI 生成图与伪造运行结果）；需要插图处登记诉求（图号、所在章节、用途、内容要素、期望形态、替代文本草案、交付状态，以 design_plan 插图诉求为基线，不得增删图号）并插入统一占位标记 `![图 {文档}-{n}：{用途}（待人工插图）](figures/{文档}/{n}.png)`；图片由人工交付后替换占位并补齐替代文本，未交付前不得声称图片存在；截图必须为真实运行结果，纳入正确性审查。

## 易理解基线

- 单段不超过 5 句。
- 首次出现的专业术语给定义或入口。
- 示例与目标受众匹配，内容难度贴合读者。
- 禁止中英混杂；术语保持原文（CANN、NPU、MindSpeed 等）。
