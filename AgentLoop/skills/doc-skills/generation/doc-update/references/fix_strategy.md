# 修复策略细则（fix_strategy）

## 严重等级处理

| 等级 | 判定 | 处理 |
| ------ | ------ | ------ |
| critical | 类型等级为 critical 的规则命中（错误信息、失效链接、缺失必选章节等） | 立即修复，修复后复核 |
| major | 不清晰描述、格式问题、缺交叉引用 | 逐项修复，语义类标注依据 |
| minor | 风格改善、措辞优化 | 批量修复 |

## 修复依据要求

- 语义正确性问题：引用代码位置或实测输出作为依据。
- 版本/配套问题：以发布说明与版本配套表为准。
- 链接问题：修复后由 doc-quality-check 重跑 lint（link 子模块）验证。
- 代码示例问题：修复后由 doc-quality-check 重跑 lint（code 子模块）验证。
- 修复 Agent 不执行 lint/评分脚本；验证归质量检查侧。

## 修改边界

- 只修改问题条目（rule_id + location）涉及的段落，不做无关重构。
- 不改变文档标题结构与已确认章节清单。
- 代码块内注释不得整条删除；注释确有错误时按问题条目修正内容（修正依据引用代码行为/参数语义）。
- 跨仓内容修改由对应仓库 owner 处理，本仓只输出建议。
- 自研仓（`contribution_mode: none`）：在本仓范围内修改中文资料（绝大多数位于 docs/zh/，examples/tests/docker 等位置的零星文件同属可修改范围），不越界到他仓。
- 三方仓遵守协作模式边界：ascend_dir 只在约定目录内修改；inline 不修改上游仓共享文件；越界问题改为输出建议。

## 验证

- 每轮修复后对照问题条目逐项确认。
- 未解决或新增问题 → 重新提交审查（循环上限与出口判定由引擎与 doc-orchestrator 控制，评分规则见 rules/rules.yaml 的 scoring 段）。
- 变更记录：问题条目（rule_id）、修改内容、验证结果、修复依据。
